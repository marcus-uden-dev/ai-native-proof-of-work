Two loops

The product loop stays intact. A system loop sits beneath it.

The product loop decides what to build. The system loop decides what should become reusable, and always through a human.

Product loop

Discover → Define → Build → Improve

Find the real constraint, choose the decision and boundary, create the smallest credible proof, then test and tighten.

System loop

Execute → Review → Detect pattern → Human gate → Promote → Next cycle

Do the work, check the output, spot what repeats, let a person decide, then turn confirmed patterns into reusable infrastructure.

Autoresearch

Broad discovery filtered into decision-relevant evidence.

Autoresearch is a scheduled, semi-automated research loop: find sources, filter for quality, extract an insight, then either promote it to a decision log or archive it.

What it filters

Source quality before insight

A finding only reaches a decision log after it clears explicit criteria — primary source, reproducible, practical, relevant, and low-hype — otherwise it is archived, not acted on.

Example

A pattern, not a headline

A recurring signal found during research is only promoted to a workflow or strategy change once it passes the quality filter and is confirmed to not duplicate an existing decision.

Daily automation

Health, drift, and opportunities become bounded next actions.

Scheduled tasks turn ongoing signals into artifacts, decisions, or a clear next test — never open-ended chores.

What it produces

An artifact, a decision, or a next test

If a scheduled run produces none of these, it is treated as noise: merged, rewritten, or disabled rather than left running.

Example

Evidence, not invented progress

A daily verifier checks prior outputs before anything ships, a weekly compiler turns confirmed product work into evidence artifacts for this site, and a kill-switch review retires routines that stop producing value. If a run finds no verified new material, it says so directly instead of inventing progress.

Promotion, human gate, and kill switch

A pattern becomes infrastructure only after a person decides.

Repeated friction converts into reusable infrastructure — an instruction, a checklist, a template, or a scheduled task — but only after review confirms it is a genuine pattern, not a one-off.

Example: A recurring project mistake became a lessons file — durable project rules that turn repeated mistakes into prevention checks, so the same error doesn't happen twice.

What becomes what

  • A repeated prompt becomes a template or instruction.
  • A repeated review step becomes a checklist.
  • A repeated schedule need becomes a scheduled task.
  • No important instruction is updated without human review — the system does not approve its own changes.
  • A confirmed pattern is promoted to the smallest durable form that fits it: an instruction, a checklist, a template, or a scheduled task.
  • A kill-switch review disables or removes routines that stop producing value — noisy, duplicate, or stale work is retired, not left to accumulate.
  • This loop improves later execution. It does not modify its own approval process or promote anything without that human decision.
