# Pricing Strategy

Last updated: 2026-05-08  
Status: Hypothesis / Not validated

## Pricing Philosophy

Pricing should reflect workflow value, not generic AI access.

The product should not be priced as “AI text generation.” It should be priced around reduced friction, better professional evidence, stronger career positioning, and reusable workflow infrastructure.

## Pricing Options Considered

| Model | Example | Pros | Cons | Status |
|---|---|---|---|---|
| Free + Pro | Free basic, paid advanced workflows | Low friction | Conversion risk | Hypothesis |
| Subscription | Monthly fee | Predictable | Requires ongoing value | Hypothesis |
| One-time setup | Fixed setup package | Easy to understand | Less scalable | Hypothesis |
| Usage-based | Pay per artifact/research run | Cost-aligned | More complex | Deferred |
| B2B license | Team workspace | Higher ACV | Longer sales | Deferred |

## Current Recommendation

Start with a one-time setup / implementation package as the most concrete pricing hypothesis.

Reason: the value is easier to explain when framed as “turn your existing work into recruiter/shareholder/client-ready proof” rather than an abstract monthly AI subscription.

## Reasoning Trail

```text
Context → Users need proof, not more content.
Options Considered → Free/pro, subscription, setup fee, usage-based, B2B.
Tradeoffs → Setup fee is less scalable but easier to validate.
Decision → Treat one-time setup as the first pricing hypothesis.
Evidence → Needs validation.
Open Questions → Will users pay before seeing recruiter/interview results?
Next Action → Test with one concrete proof-of-work repo or portfolio package.
```
