# PKM Pricing Strategy

Last updated: 2026-05-11
Status: Deferred hypothesis / Not validated

## Project Scope

Project: PKM.

Role in portfolio: supporting proof point for knowledge workflow design.

## Pricing Philosophy

PKM should not be priced as generic note storage. If priced at all, pricing should reflect retrieval quality, learning support, and reduced knowledge-work friction.

## Pricing Options Considered

| Model | Pros | Cons | Status |
|---|---|---|---|
| Free local/self-hosted | Low friction | Weak commercial validation | Hypothesis |
| Individual subscription | Simple | Requires sustained daily value | Hypothesis |
| One-time setup | Concrete for power users | Less scalable | Hypothesis |
| Team license | Higher value | Requires collaboration and admin scope | Deferred |

## Current Recommendation

Defer pricing until core daily-use value is validated across ingestion, search, learning, and browser capture.

## Reasoning Trail

```text
Context → PKM value is not yet validated through daily use.
Options Considered → Free/self-hosted, individual subscription, one-time setup, team license.
Tradeoffs → Pricing too early can overstate commercial confidence; waiting preserves credibility.
Decision → Defer pricing until the core workflow is validated.
Evidence → Needs validation.
Open Questions → Which workflow creates enough repeated value to justify payment?
Next Action → Verify one end-to-end daily-use path.
```
