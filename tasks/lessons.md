# Lessons

- Context: scheduled weekly proof-of-work runs in a shared local worktree; Corrected rule: run the clean-state guard before editing, stop if any staged/unstaged/untracked state exists, and finish a successful run with an explicit-path commit plus a passing final clean-state check; Prevention check: do not start or report a compiler run as complete unless `scripts/Test-CleanGitState.ps1` passes at the corresponding boundary.
- Context: documenting Marcus-created custom skills as proof-of-work; Corrected rule: document custom skills through sanitized problem/solution workflow cases and templates, linking to safe artifacts while keeping raw local skill prompts and private paths out of recruiter-facing docs; Prevention check: before promoting a skill claim, verify the problem, before/after workflow, evidence status, tradeoff, and redaction boundary are explicit.
- Context: local proof-of-work indexing across Codex, Claude, and shared agent folders; Corrected rule: keep projects and source roots separated as Codex execution evidence, Claude strategy/planning evidence, and shared skills/workflow infrastructure; Prevention check: before updating recruiter-facing artifacts, verify the source layer for each claim and avoid merging separate project histories into one bucket.
- Context: recruiter-facing proof-of-work positioning; Corrected rule: make concrete product projects the primary proof points, especially job-agent, with PKM and the household budget app as supporting evidence, while keeping the automation/compiler documented as the repeatable operating layer; Prevention check: before updating value proposition, recruiter summaries, or CV bullets, verify that the documentation does not let automation overshadow the actual product projects.
- Context: strategy documentation for the proof-of-work portfolio; Corrected rule: keep product strategy scoped to the actual product repo or project under `strategy/<project>/` with the canonical `product/`, `business/`, `market/`, and `decisions/` subfolders, and reserve portfolio evidence-layer strategy for the portfolio operating layer; Prevention check: before editing strategy links or claims, verify whether the claim is about job-agent, PKM, household budget app, or the portfolio compiler.
- Context: Mermaid diagrams in recruiter-facing proof-of-work docs; Corrected rule: diagrams must show the actual product portfolio and evidence flow, not imply the proof-of-work repo is the product, and should use compact labels/orientation without long cyclic return arrows that GitHub may clip; Prevention check: render all Mermaid blocks, inspect dimensions, and search for backward loop arrows after diagram edits.
- Context: making the proof-of-work system reusable by other users; Corrected rule: keep clone/fork/template adoption material in `template/` so the main repo stays recruiter-first while preserving a standalone, LLM-agnostic seed; Prevention check: before changing bootstrap, import, or navigation docs, verify `template/README.md` is linked from main entry points, avoids Marcus-specific private evidence, and treats tool-specific prompts as adapters.
- Context: recruiter-facing lead-project handoff documentation; Corrected rule: verify setup files, env examples, ports, commands, and agent entrypoints against the current source repo before updating `case-studies/JOB_AGENT_INSTALL_AND_HANDOFF.md`; Prevention check: before weekly handoff edits, confirm the exact files exist in the source tree and downgrade any unverified claim to `Needs Review`.
- Context: recruiter-facing proof-of-work can include personal learning and consumption signals; Corrected rule: summarize podcasts, X follows, and web visits as aggregate information-diet context with evidence labels, never as measured learning or listening time unless a stats export supports it; Prevention check: before publishing consumption evidence, remove raw feeds, account identifiers, local paths, and private browsing trails.
- Context: recruiter-facing proof-of-work should include implemented workflow improvements when they are concrete; Corrected rule: treat Claude artifacts, Codex intake flows, tasks/lessons, design rules, frequent skills, automations, global logs, and template materials as supporting workflow case studies, while keeping product projects as the primary proof; Prevention check: before adding workflow claims, verify there is a sanitized artifact link or mark the case `Needs Review` / `Planned`.
- Context: weekly proof-of-work sync when the lead product repo is not directly accessible; Corrected rule: keep the last verified source date explicit and downgrade fresher product-status claims to `Needs Review` until a dated source summary or direct verification exists; Prevention check: before updating handoff or product-status freshness, confirm the lead source repo is accessible in the current runtime or cite the last direct verification date.
